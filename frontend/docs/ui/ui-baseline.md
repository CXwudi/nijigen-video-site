# UI Baseline

## shadcn/ui on Base UI - The stack

One sentence: shadcn/ui provides the component abstraction and tokens, Base UI provides the a11y and interactivity.

- **Components**: copy-and-own shadcn/ui components under `src/components/ui`, generated by the official CLI with the `base-nova` style and the `@base-ui/react` primitives (see `components.json`).
- **Tokens**: all styling flows through semantic CSS variables (`--background`, `--foreground`, `--primary`, …) defined in `src/styles.css` under `:root` / `.dark`, exposed to Tailwind via `@theme inline`. Custom semantic tokens (e.g. Snow Miku `--success`/`--warning`/`--info`) follow the same pattern.
- **Theming**: light tokens are the default; dark mode is class-based (`.dark`), driven by `ThemeProvider` in `src/components/theme-provider.tsx` with the official TanStack Start `ScriptOnce` pattern (no FOUC, no hydration mismatch).

## Rules

- Prefer shadcn/ui components from `src/components/ui` over hand-rolled controls. They already encode Base UI's accessibility (roving focus, keyboard navigation, focus-visible rings).
- Do not style with raw color utilities. Use token utilities (`bg-primary`, `text-muted-foreground`, `border-border`) so light/dark theming keeps working.
- To customize: edit the copy in `src/components/ui/*`, never the token names.
- Dark mode variants go through the `dark:` variant (class strategy), not `prefers-color-scheme`.
- Interactive primitives come from `@base-ui/react` (menu, select, dialog, tabs, tooltip, …). Base UI uses the `render` prop for polymorphism (e.g. `<Button render={<a href="…" />}>`), not `asChild`.
- If the shadcn registry adds a new component, prefer `pnpm dlx shadcn@latest add <name>` over manual copy to stay in sync with the official source.
